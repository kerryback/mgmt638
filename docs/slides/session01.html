Course Overview

The subject

Quantitative investing. Predicting stock returns, and finding out how little is predictable.

What the Model Is Actually Good For

One claim, and we spend six weeks testing it.

A language model’s comparative advantage is turning text into a number. Everything downstream — sizing, portfolio construction, execution — is an optimization problem the model does not help with.

The corollary is the useful part: it is not going to trade for you, but it will write every line of the machinery that does.

It Writes Code

That Is the Whole Trick

Almost everything useful the model does, it does by writing code and running it.

Usually Python or JavaScript. The code runs on a server — here, on the lab machine — not inside the model.

You are not asking it for an answer. You are asking it for a program that produces an answer, and the program is something you can read.

One Capability, Six Directions

Excel workbooks with live formulas Charts and figures
PowerPoint decks Data analysis and statistics
Word documents Web apps and dashboards

These are not six features somebody built. They are one capability — write code, run it — pointed in six directions.

What That Looks Like Underneath

You ask

Read these four PDFs. Pull out every number either side cites about market share, note which ones disagree, and put it in a table.

What actually happens

Each PDF is converted to text. The text is read. A Python script builds the table. The table is written to a file.

Nothing there is a document feature. It is code execution, pointed at file formats.

Numbers Need Code

The problem

To a next-token predictor, “47.3%” is exactly as plausible as “52.1%”.

Mental math, rankings, comparisons, aggregations — all unreliable, and the wrong number arrives with complete confidence.

The fix

Insist on code, and insist that it run.

Arithmetic stops being prediction and becomes computation — and you can read afterward what it actually did.

Chatbots and Agents

First, a Chatbot

You, a program, and a model. The model reads text and writes text. That is the entire capability.

It cannot open a file, run a calculation, look up today’s date, or check whether what it just told you is true.

The chatbot passes along your prompt — plus the system prompt and everything said so far in the conversation — and hands back the reply.

An Agent Is a Chatbot with Tools

  1. The agent sends the prompt, the history, and a list of tools it has
  2. The model answers: use tool X, with these arguments
  3. The agent runs tool X and reports the result back, with instructions for reading it
  4. The model decides what to do next — another tool, or an answer for you

The model never runs anything. It emits requests; the agent executes them. Those step-3 instructions are the tool harness, and some are far better than others.

Why GitHub

Your group shares one repository, not a folder of attachments.

Mailing notebooks around breaks down by the second week. GitHub keeps one copy that everyone edits, records who changed what and when, and lets two of you work the same afternoon without overwriting each other.

You Do Not Type Git Commands

Same bargain as the code. You say what you want; GLM runs it.

Git has a deserved reputation for cryptic errors. You do not need to learn it — you need to know what you are asking for, and to check that it happened.

There is exactly one step you do yourself, and it is on the next slide.

Prompting

Good Enough Prompting

Most of the prompt engineering advice from a few years ago is now either useless or actively harmful.

Say what you want, not how to do it

“I want to compare revenue across countries — how should we show it?”

beats

“Make a bar chart, sorted descending, gridlines off, 12pt labels.”

If it does not work, try again

Rephrasing is cheap. Treat it as an infinitely patient colleague with a poor memory.

Plan Before You Act

Use plan mode, or just add: plan how you will do this before you start.

Why it works — knowledge

Planning pulls the relevant considerations into the conversation. It then answers in light of what it just retrieved, rather than from base rates.

Why it works — scale

It breaks the work into steps you can check one at a time. Failures stay small and local instead of surfacing at the very end.

Confirm It Understood

Ambiguity does not produce a question. It produces a confident answer to a question you did not ask.

Tell GLM, before it starts

Tell me what you are about to do and what you are assuming.

Correct it in one sentence, then say go ahead. This is the cheapest habit in the course and it will save you the most time.

It Is a Prediction Machine, Not a Colleague

Suppose it told you last week that method A beats method B. Today you ask it to do the task.

What it will do

If “A beats B” is not in this conversation, and B appeared more often in its training data, it will probably use B.

Why

Knowledge in the weights is not knowledge in use. Something has to pull it into the conversation before it can act on it.

Tunnel Vision

Prediction also means momentum. Once it has started down a path, continuing that path is the likeliest next step.

You will watch it hit a roadblock, find a way around, hit another, find another way around — tenaciously, exhaustively. What it rarely does is go back and ask whether a different path was better all along.

Restate the goal, not the obstacle. That gives it permission to abandon the path instead of defending it.

What Not to Do

Skip Why
“Think step by step” Reasoning models already do, in hidden tokens
“Take a deep breath” Measurably useless now
“CRITICAL! NEVER EVER …” Overtriggers, and gets worse results
Stacked personas “You are an expert X” can help tone; three of them does not

Direct task framing wins. Say what you want, say what done looks like, say what to avoid.

Analysis, Without a Spreadsheet

Go and Get the Data

No file to upload, no API key to paste. Ask.

Tell GLM

Get monthly returns for WMT and SPY since 2020 from Yahoo Finance. Scatter plot, SPY on the horizontal axis, with a regression line.

What You Just Did

The slope of that line is Walmart’s market beta. You estimated a CAPM regression by asking for a scatter plot.

The code ran on a machine in the cloud. Nobody at Yahoo, and nobody at Anthropic, built a beta calculator.

Look at the Code

Tell GLM

Show me the code you ran.

You do not need to write Python to read it. Find the line that computes the returns.

Any number that matters comes out of code you can open. That rule applies to every session in this course.

Push It Further

Tell GLM

Add the other Dow components and rank them by beta.

Annotate the three months with the largest residuals and tell me what happened in each.

Watch whether those explanations are sourced or invented.

Put It Somewhere

Tell GLM

Put the chart and a short written summary in a PowerPoint deck.

Then download it and open it on your laptop.

The chart, the layout, the text — all produced by code GLM wrote and ran.

Validation

What Could Go Wrong

You asked for a chart of betas and you got one. Now what?

No answer

Easy. You notice immediately.

Wrong kind of answer

Also easy. A pie chart when you wanted a scatter.

Right kind, wrong numbers

This is the one. It looks exactly like the answer you wanted.

The Trap

Yahoo gives you two closing prices for every day: Close, and Adj Close, which is adjusted for dividends and splits.

Returns from the wrong one are wrong — and Walmart both pays a dividend and split three-for-one in 2024.

Tell GLM

Recompute the betas both ways and show me the difference.

Where the Errors Come From

Misunderstanding

Your instruction was ambiguous.

Ask it to state its plan before it starts.

Silent assumptions

It chose something you never authorized — which price column, which date range.

Ask it to walk through what it did.

Coding errors

Rare. The code either runs or it does not.

Hallucinations

It is not lying. It is predicting the next token, and a plausible citation is exactly as predictable as a real one.

The risk is highest when the answer is unknown or unfindable — an obscure statistic, a citation that may not exist, a number that was never public. Asked a question with no available answer, it will still produce one.

Make it search

And give you the sources.

Check the sources

Click them. A real-looking citation to a paper that does not exist is the classic failure.

Make it compute

Any number that matters comes out of code.

Never Ask “Is This Good?”

Training on human feedback teaches that agreement earns high ratings. Ask “is my plan sound?” and it will find reasons that it is.

Invert the question

What is the strongest argument that this recommendation is wrong?

One step further: have it play a specific skeptic — a referee, a regulator, the desk that has to trade this.

Set a Critic on It

GLM can dispatch a subagent: a fresh instance, no memory of this conversation.

Why it is worth something

It sees the instructions, not the reasoning behind the first answer. It has nothing to defend.

Give it a mandate: find every factual error, logical gap, and unsupported assumption. Do not summarize — find flaws.

The catch

Two agreeing runs are evidence, not proof. They share a model and they share your ambiguous question.

Anything that both produces work and checks its own work is grading its own homework.

Three Checks Before You Trust It

Where did this come from?

A citation you can click, a file you can open, or code you can read. If none of the three, treat it as a guess.

What did it assume?

Every unstated choice was made for you. Ask what it decided that you did not specify.

Would I catch it if it were wrong?

If not, that is the part to check by hand — not the part you already understand.
